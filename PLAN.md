## 🐍 Python Scripts

### `src/validate_data.py`
- Load `data/users.json`
- Validate each entry: `github_username` is required and non-empty, `profile_url` matches `https://github.com/{username}` (case-insensitive), no duplicates by username
- Exit code 1 on failure with clear error message

### `src/process_issue.py`
Called by the pipeline workflow when an issue is opened/labeled with `add-developer` or `remove-developer`.

**Arguments**: `issue_number`, `issue_title`, `issue_body` (all as CLI args or env vars)

**Logic for add:**
1. Parse issue body (GitHub issue form YAML format) to extract `github_username` and `location`
2. Validate `location` matches any alias in `config/metrics.json` location_aliases
3. Check username is not in `data/removed_users.json`
4. Check for duplicate in `data/users.json`
5. Fetch basic GitHub profile via REST API (`GET /users/{username}`) — needs `GITHUB_TOKEN`
6. If profile doesn't exist or is not public, reject
7. Append to `data/users.json` with basic stats, sorted by username alphabetically
8. Output status string for the workflow to parse: `ADDED`, `DUPLICATE`, `INVALID_LOCATION`, `PROFILE_NOT_FOUND`, `BLOCKED`, `MANUAL_REVIEW`

**Logic for remove:**
1. Parse username from issue body
2. If self-removal (checkbox checked), move entry from `users.json` to `removed_users.json` with reason `self_removal`
3. If third-party, flag for `MANUAL_REVIEW`
4. Output: `REMOVED`, `NOT_FOUND`, `MANUAL_REVIEW`

### `src/enrich_data.py`
Fetches enriched metadata for all users in `data/users.json` and writes `data/users-enriched.json`.

**Key behaviors:**
- Uses GitHub GraphQL API for batch efficiency (fetch up to 20 users per query using aliases)
- Supports multiple tokens via `GH_TOKENS` env var (comma-separated) with rotation on rate limit
- **Incremental updates**: skip users enriched in the last 24 hours (check `enriched_at`) UNLESS `--force` flag is passed
- Fetch: avatar, bio, company, website, followers, following, repos (top 10 by stars, non-fork), contribution stats (90-day window via `contributionsCollection`), top languages
- Compute `activity_score` using weights from `config/metrics.json` (normalize each metric using min-max across the full dataset)
- Apply `overrides.yml`: mark `featured: true` for listed usernames
- Write `data/users-enriched.json` (full enriched array)
- Also write daily snapshot to `data/{YYYY-MM-DD}.json` (same format)
- Handle rate limits gracefully: sleep and retry, rotate tokens

**GraphQL Fragment (use this structure):**
```graphql
fragment UserProfile on User {
  login name avatarUrl bio location company websiteUrl createdAt
  followers { totalCount }
  following { totalCount }
  repositories(first: 10, orderBy: {field: STARGAZERS, direction: DESC}, isFork: false) {
    nodes {
      name description url stargazerCount forkCount
      primaryLanguage { name }
      repositoryTopics(first: 5) { nodes { topic { name } } }
      pushedAt isArchived isFork
    }
    totalCount
  }
  contributionsCollection {
    totalCommitContributions totalPullRequestContributions
    totalIssueContributions totalPullRequestReviewContributions
    restrictedContributionsCount
    contributionCalendar { totalContributions }
  }
}
```

### `src/build_search_index.py`
- Read `data/users-enriched.json`
- Build lightweight array of compact objects (abbreviated keys for size)
- Write to `data/search-index.json`
- Log count and file size

### `src/generate_readme.py`
- Read `data/users-enriched.json`
- Generate `README.md` with:
  - Title, badges (pipeline status, collect-stats status, last commit, license, view counter)
  - Top 25 by overall score, by followers, by stars, by public repos — markdown tables with avatar, username link, score, followers, stars
  - Rising stars: most followers gained recently, most stars gained recently
  - Full directory table (all devs, sorted by score desc)
  - The README must pass `awesome-lint` — include Contents section, proper structure

### `src/bulk_add_developers.py`
- Accept a CSV or newline-delimited list of usernames
- For each: validate location via GitHub API, add to `users.json` if not duplicate/blocked
- Used for the initial bulk import — not part of the automated pipeline

### `tests/`
Write `pytest` unit tests with mocked HTTP responses for:
- `test_process_issue.py`: add valid user, add duplicate, add blocked user, invalid location, remove self, remove not found
- `test_validate_data.py`: valid data passes, missing username fails, duplicate fails, wrong URL fails
- `test_enrich_data.py`: token rotation, incremental skip logic, score normalization

- Setup Python 3.12
- `pip install -r requirements.txt pytest pytest-cov`
- `pytest --cov=src --cov-report=xml -q`

- Runs only when: `github.event_name == 'issues'` AND issue has label `add-developer` OR `remove-developer`
- Checkout with `fetch-depth: 0`
- Setup Python 3.12, install deps
- `git config` bot identity
- `git pull --rebase origin main` (get latest before modifying)

- Retry push loop (5 retries with rebase)
- Comment on issue with result and close/label appropriately

- `npm run build` (runs `eleventy`)
- `actions/configure-pages@v4`
- `actions/upload-pages-artifact@v3` with path `_site`
- Deploy: `actions/deploy-pages@v4`

### `.eleventy.js` (ESM)
```js
import { DateTime } from "luxon";

export default function(eleventyConfig) {
  eleventyConfig.addPassthroughCopy("data/*.json");
  eleventyConfig.addPassthroughCopy("assets");
  eleventyConfig.addPassthroughCopy("site/robots.txt");
  eleventyConfig.addPassthroughCopy("CNAME");

  eleventyConfig.addFilter("readableDate", (d) =>
    DateTime.fromISO(d, { zone: "utc" }).toLocaleString(DateTime.DATE_FULL)
  );

  eleventyConfig.addFilter("slugifyLang", (str) => {
    if (!str) return "";
    return str.toLowerCase()
      .replace(/\+/g, "p").replace(/#/g, "sharp")
      .replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "");
  });

  eleventyConfig.addFilter("limit", (arr, n) => arr.slice(0, n));
  eleventyConfig.addFilter("sortBy", (arr, key) =>
    [...arr].sort((a, b) => (b[key] || 0) - (a[key] || 0))
  );
  eleventyConfig.addFilter("json", (val) => JSON.stringify(val));

  return {
    dir: {
      input: "site",
      output: "_site",
      includes: "_includes",
      data: "_data"
    },
    templateFormats: ["md", "njk", "html"],
    markdownTemplateEngine: "njk",
    htmlTemplateEngine: "njk"
  };
}
```

### `site/_data/languages.js`
```js
export default async function() {
  // Derived from enriched data — return top languages with dev counts
  const { default: getEnriched } = await import("./enriched.js");
  const enriched = getEnriched();
  const langMap = {};
  for (const dev of enriched) {
    for (const lang of (dev.all_languages || [])) {
      if (!lang) continue;
      if (!langMap[lang]) langMap[lang] = [];
      langMap[lang].push(dev);
    }
  }
  return Object.entries(langMap)
    .map(([name, devs]) => ({ name, slug: name.toLowerCase().replace(/\+/g,"p").replace(/#/g,"sharp").replace(/[^a-z0-9]+/g,"-"), count: devs.length, top_devs: devs.slice(0,5) }))
    .sort((a,b) => b.count - a.count);
}
```

### `site/_data/stats.js`
```js
export default async function() {
  const { default: getEnriched } = await import("./enriched.js");
  const enriched = getEnriched();
  if (!enriched.length) return {};
  const totalStars = enriched.reduce((s, d) => s + (d.total_stars || 0), 0);
  const totalFollowers = enriched.reduce((s, d) => s + (d.followers || 0), 0);
  const allLangs = enriched.flatMap(d => d.all_languages || []).filter(Boolean);
  const langCounts = {};
  for (const l of allLangs) langCounts[l] = (langCounts[l] || 0) + 1;
  const topLang = Object.entries(langCounts).sort((a,b) => b[1]-a[1])[0]?.[0];
  return {
    total_devs: enriched.length,
    total_stars: totalStars,
    total_followers: totalFollowers,
    top_language: topLang,
    avg_score: +(enriched.reduce((s,d) => s+(d.activity_score||0),0)/enriched.length).toFixed(1)
  };
}
```

## 📌 Key Implementation Rules

1. **No live GitHub API calls from frontend** — all data is pre-fetched by Python scripts and baked into JSON files at build time. The frontend only reads static JSON.
2. **Tailwind via CDN only** — no PostCSS, no npm build step for CSS. Use `<script src="https://cdn.tailwindcss.com">` in base.njk to avoid build complexity.
3. **Eleventy 3.x ESM** — use `export default` in `.eleventy.js` and set `"type": "module"` in `package.json`.
4. **Dark mode** — every page must support dark mode via Tailwind's `dark:` classes, with a toggle that persists to `localStorage`.
5. **Fuse.js search** — search runs entirely in the browser against `search-index.json`. No server, no API.
6. **Incremental enrichment** — `enrich_data.py` skips users enriched within 24 hours unless `--force` flag. Prevents rate limit exhaustion on the 3500+ user list.
7. **Token rotation** — `enrich_data.py` rotates through multiple `GH_TOKENS` on rate limit hit (HTTP 403 or `X-RateLimit-Remaining: 0`).
8. **Concurrency guard** — all deploy workflows use `concurrency: group: deploy-${{ github.ref }}, cancel-in-progress: false` to prevent race conditions on simultaneous pushes.
9. **Git push retry** — all workflows that push data use a 5-attempt retry loop with `git fetch && git rebase` before each retry.
10. **awesome-lint compliance** — `README.md` must pass `npx awesome-lint README.md`. The `generate_readme.py` script must produce a lint-compliant README: proper Contents section, no broken links in the header area, correct Awesome badge URL.
11. **Pagination** — the issue processing and deployment are separate jobs with clear dependencies to avoid running site deployment when only a data validation failed.
12. **`CNAME` passthrough** — ensure `.eleventy.js` copies `CNAME` to `_site/` so the custom domain survives each deployment.
13. **Score normalization** — activity scores are min-max normalized across all developers in the dataset, NOT globally hardcoded. Re-normalize on every enrichment run.
14. **Daily snapshots** — `enrich_data.py` writes `data/{YYYY-MM-DD}.json` as an archive. Old snapshots (>30 days) should NOT be auto-deleted (they power the growth charts on the stats page).

## 🚨 Root Causes of the Old Broken Pipeline (Fix These)

The v1 CI/CD pipeline broke due to a combination of:
1. **Eleventy 2.x → 3.x CJS/ESM mismatch** — old `.eleventy.js` used `module.exports` (CJS) but Eleventy 3.x expects ESM or explicit CJS. Fix: use ESM throughout (`export default`, `"type": "module"`).
2. **Tailwind PostCSS build step failing** — the old setup likely had a Tailwind build step that broke due to version incompatibilities. Fix: switch to Tailwind CDN, zero build complexity.
3. **`deploy-site.yml` workflow was missing** (the copilot instructions referenced it, the workflows list didn't have it). Fix: consolidate into `pipeline.yml`'s `build-and-deploy` job and `enrich.yml`'s `deploy` job.
4. **`awesome-lint` failing on auto-generated README** — the generated README likely had formatting issues. Fix: ensure `generate_readme.py` produces lint-compliant output.
5. **Race condition on simultaneous issue processing + push** — multiple issues opening at the same time caused push conflicts. Fix: concurrency guards + robust retry loop.
6. **`site/_data/*.js` files using `require()` (CJS)** in an ESM project. Fix: rewrite all `_data` files as ESM with `export default`.
